Review the Student 1 feature architecture: user profile management (profile CRUD and
resume storage, applicant self-service).

This feature owns its own frontend (student-1-frontend), backend/API
(student-1-backend), and database (student-1-db) tiers. It reuses the shared auth
service (shared-api/shared-db) for identity (users and sessions) via an HttpOnly
session_token cookie, and never stores first/last name or credentials in its own
profiles table.

Resumes (PDF only, 5MB max) are stored as a BLOB in student-1-db, owned entirely
by this feature; resume-level routes live at /resume/{resumeId} rather than
nested under /profile/{id}/resume/{resumeId}. The backend renders HTML
fragments for an HTMX frontend (no JSON API), matching student-2/3's pattern.

The AI resume-autofill capability (suggest professional title/summary/interests from
an uploaded resume, with review/accept/discard) is not yet implemented in this
release; it is blocked on the shared ai-services/ai-mode service, which is currently
a team-wide placeholder.
